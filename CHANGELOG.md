# Workspaces changelog

What changed between versions, in the words you'd notice it. `RECIPE.md`
describes the whole thing as it is now; this file says what's new since the
version you have (`mods/ws-switcher/VERSION` in your copy). To update, see
"Updating" in the README.

## [Unreleased]

## [0.24.0] - 2026-11-24

### New
- **Automations v2: shell scripts, login startup, guardrails and richer triggers.** An automation can now run a shell script with no agent (`run: shell`, with `shell: bash|zsh|sh`): it runs in the background (or in a tab with `terminal: true`) with what set it off as `$HERDR_…` variables, its exit code, duration and output go to History (`~/.herdr/runner/logs/`), and a failure is pinned in the bell. Like a check, a script runs only once you've allowed its exact text (Create and Save allow it; one added another way waits for Allow this script). The Automations screen marks scripts with a terminal icon and a Shell pill, has a monospace Script box with Try it, a Preview that runs the check and shows the filled-in prompt or the script and its variables without starting anything, a Log button on a script's runs, an optional `{{text}}` for Run now on a `link` one, and under Details: Runs as, new When chips (PR review requested, PR merged, CI failed, After run, Startup / Wake), a multi-line Check first with Skip or Run anyway for the same output, and Safety & delivery (timeout, notifications, if missed). New `when:` forms: `github <repo> pr review-requested`, `pr merged`, `ci failed`, `pr|issue labeled:<name>`, `startup`, `wake`, `automation done <name>` (after a run that did its work, not one with nothing to do) and `automation failed <name>` (after a failure or a timeout; with `{{output}}`, `{{upstream}}`, `{{outcome}}`). New keys: `timeout:` (scripts 2 minutes, agents none by default; a run past it while it still works is stopped and pinned, a script with what it started, keeping what it printed), `notify:` (problems, results, all or none; agents tell results, so "<name> started" toasts are gone unless you ask for `all`; scripts only problems), `missed:` (run, skip or always) and `dedupe:` (always runs a schedule's check even when it prints the same). A new Settings > Automations section holds Keep running (moved from Agents), Start at login (a macOS LaunchAgent, `~/Library/LaunchAgents/dev.herdr.ws-runner.plist`, that starts the background runner after a reboot without opening Herdr or starting herdr-core until an agent automation fires), Max parallel agent runs (2 by default; the rest queue), Quiet hours for the desktop sound and the Drafter (Auto, Claude, Codex, Antigravity or Pi; Draft it can now write a shell script when no agent is needed). History shows a script's run with its shell, exit code, how long it took and its output, with Run again and Open log in Files; agent runs get Run again too, and queued and timed-out runs say so. History keeps 25 runs per automation (500 in all) instead of the last 100. `herdr-ws-run --add` takes `--shell`, `--terminal`, `--timeout`, `--notify`, `--missed` and `--dedupe`, and `herdr-ws-runner` takes `--login on|off|status`. To update, copy `mods/ws-switcher`, `mods/ws-automations`, `mods/ws-history`, `mods/ws-settings`, `mods/ws-notifications`, `mods/ws-agents`, `mods/ws-status` and `mods/ws-files` (`settingsfacts.js` is one file, copied in each, and now in `ws-automations` too; `autofacts.js` is new in `ws-switcher` and `ws-automations`).

## [0.23.0] - 2026-11-23

### New
- **A notifications bell.** A bell at the right end of the tab bar, right of Views, lists what needs you and what finished in every workspace, each with its workspace's mark and where it is. Needs you stays at the top until it's resolved: an agent or a helper waiting on you, an automation run stuck at a question, a check nobody allowed (said once for an automation of every workspace) or that fails, a card's pull request failing, with changes asked for or conflicting while no agent works on it. Updates are unread until you click them: an agent or an automation run that finished (once, when its outcome is known; not one with nothing to do; a failed one stands out), an automation that didn't start or was missed while Herdr was closed, a card's pull request ready to merge, merged or closed, a machine that needs a login, the background runner that didn't start. One click goes there: the agent, the run (its tab, or History's Automations side with that run open), the card's dialog on its board, the automation. Mark all read, × and Clear read tidy the list, updates go after 7 days, and the count is red while anything needs you, blue for unread updates only. It remembers in `~/.herdr/notifications.json`, so a restart, and the background runner's news from while Herdr was closed, keep their place (on first start, what's there already counts as read). A pull request's toast now opens its card. Settings > Features has a Notifications bell switch; `ws-tabs.notifications` (bind it in `keys.json`) opens and closes the list. To update, copy the new folder `mods/ws-notifications` and `mods/ws-switcher`, `mods/ws-tabs`, `mods/ws-toast`, `mods/ws-history`, `mods/ws-board`, `mods/ws-settings`, `mods/ws-agents`, `mods/ws-status` and `mods/ws-files` (their `settingsfacts.js` is one file).

### Fixed
- **The switcher's header is just the workspace.** The count of spaces and the dot for another workspace's agents are gone from it (and from the narrow rail): the spaces list shows the spaces, and the bell says what needs you and where. The switcher's menu still marks each workspace. Comes with the bell's update above.

## [0.22.0] - 2026-11-23

### New
- **Files' defaults in Settings > Files.** A new Files section in the package's Settings window (Features, Agents, Files, Experimental) and a `"files"` block in `~/.herdr/settings.jsonc`, each key with a comment saying what it does: what Markdown and SVG open in (Preview, Source or Split), the app Open in starts with before it has remembered one for a kind of file (Automatic: the editor first, or any editor or app it lists), whether ignored files start shown, where a Cmd-clicked path opens (beside the terminal, Files full size, or Off to leave it to the system as before) and what Files takes (text, images and folders, or everything, binaries included). Every value starts as Files behaved before, a change applies at once to every open Files and to Cmd-click without a restart, and a hand edit in the file within 10 seconds. To update, copy `mods/ws-settings`, `mods/ws-files`, `mods/ws-agents`, `mods/ws-switcher` and `mods/ws-status` (their `settingsfacts.js` is one file, copied in each).
- **Files view: edit, Markdown/image preview, Open with…, and Cmd-click in Herdr.** Files now has a Files | Search rail beside the open file (one column under 640px, as beside a terminal): a filter box, file-type icons, git marks and the branch, Show ignored, and content search (`rg`, else `grep`) whose matches open at their line. Text, code, Markdown and SVG are edited in place with an explicit Save (⌘S / Ctrl+S) and Discard, never saved on their own; a file changed on disk reloads when nothing is unsaved, else offers Overwrite or Reload from disk and keeps your draft, and a file deleted under a draft offers Save as new. Markdown and SVG get Source | Preview | Split (Markdown opens in Preview; the mode you pick is kept), links in a preview open here or in the browser, and images show as they are. Files over 400 KB, or on another machine, are read-only. Open in … ▾ opens the file in an installed code editor (at the cursor's line) or any app macOS offers for it, with Reveal in Finder and Copy path, and remembers your pick per extension in `~/.herdr/files-prefs.json`. Cmd-click (Ctrl-click) a path in a terminal or an agent's output, `src/app.ts:42` included, and text, code, Markdown, SVG, images and folders open in Files beside that terminal (reusing the tab's Files pane), while PDFs, archives, media and other binaries still go to the system; on another machine's space it opens full size, and with no space in a dialog. Changes has an Open in Files icon on the selected file, and Settings > Agents' Herdr guide (Edit, Write one) now opens `~/.herdr/AGENTS.md` in Files. To update, copy `mods/ws-files`, `mods/ws-changes`, `mods/ws-switcher` and `mods/ws-settings`, and add `"link_handlers": ["ws-files"]` at the top of `layouts/workspaces.json` (Herdr also adds it by itself the first time it sees the mod's link rules).

## [0.21.0] - 2026-11-23

### New
- **History says what each automation run did.** On the Automations side, a run's grey line is now the start of what its agent said at the end, and its word says how it went: done, failed, nothing to do, needs you, running, or no report (its tab was closed while it worked). A click opens the whole report, when it ran and for how long, and Open the automation (the button moved there; Resume stays on the row, no longer the loudest button). To tell done from failed, every automation run's agent is now asked to end its last message with an outcome line (`Outcome: done`, `Outcome: failed` or `Outcome: nothing to do`), which History shows as the word and leaves out of the report; runs from before and agents that skip it say "done". Reports are read for Claude Code, Pi and Antigravity runs. History reads every transcript of the last 90 days once more on its first read. To update, copy `mods/ws-history` and `mods/ws-switcher`.

### Fixed

## [0.20.0] - 2026-11-23

### New
- **Views: every screen opens the same way, from one menu.** A "Views" button at the right end of the tab bar lists the shown space's Changes and Files and the workspace's Board, Notes, Worktrees and History. A click opens one full size, in place of the terminals with the status bar still under it, and pins its pill before the tabs (again: back to the terminals); the split icon on its row, or ⌥ with the click, opens it beside the shown tab's terminals as an ordinary pane you can drag, zoom and close. One already a pane in that tab is focused instead of a second. While a view is shown full size, "Beside <tab>" next to Views (or a pill's right-click, Move beside) moves it into a pane. Changes and Files belong to the space they were opened in (their pills show only there); the other four to the workspace, as before. With more than three pills the ones not shown are only their icon, and a zoomed tab shows an Unzoom chip instead of " Z". In a workspace with no spaces the tab bar and status bar stay, + makes a space there and the four workspace views still open (Changes and Files say they need a space); with All spaces, History opens full size with every conversation. Views you've turned off in Settings > Features aren't offered, and their panes opened from Views close. Commands for keys: `ws-tabs.view/<view>` (full size), `ws-tabs.beside/<view>` and `ws-tabs.views` (the menu; again: closes it), with `<view>` one of `changes`, `files`, `board`, `notes`, `worktrees`, `history`; they work with the sidebar hidden. The package binds no keys; the RECIPE's Views section has lines for `keys.json` (⌘⇧G, ⌘⇧E, ⌘⇧B, ⌘⇧N, ⌘⇧H, with ⌥ for beside; free on macOS, not on Linux or Windows), and the menu shows a key once it's bound.
- **What moved.** Board, Notes, Worktrees and History open only from Views now: the Board and Notes buttons beside the workspace switcher, the switcher menu's "Open … board", "Open … notes" and "Open … worktrees" rows, History in the sidebar footer (now 125px) and the + menu's "Resume a conversation…" and "Notes" rows are gone. Herdr's Files and Changes side panel is gone too: Files and Changes are views, from the package's own copies of Herdr 0.1.17's (`ws-files`, `ws-changes`). As a pane they follow the terminal you last used in their tab, so clicking into them doesn't switch them to the space's folder, and that's kept across a restart; full size they follow the space's shown tab. They read nothing while out of sight. Each view opened as a pane has one header (Herdr's) and one slim row of its controls, and fits a narrow pane: Board opens as a list with two-line rows, Notes shows its list or one note ("← Notes"), History puts its search up top. The `ws-switcher.board`, `.notes`, `.worktrees` and `.history` commands still work. To update, copy `mods/ws-tabs`, `mods/ws-switcher`, `mods/ws-new-menu`, `mods/ws-chrome`, `mods/ws-settings`, `mods/ws-agents`, `mods/ws-status`, `mods/ws-board`, `mods/ws-notes`, `mods/ws-history` and `mods/ws-worktrees`, and the two new folders `mods/ws-changes` and `mods/ws-files`; delete `mods/ws-tabs/fit.js`, which nothing uses now. Then copy `layouts/workspaces.json` (and click your sizes again), or make its four edits by hand (RECIPE's Built from has them in full): wrap `center` in the root row in a column `work-area` that holds the `tabs` block, `center` and the `status` block (moved out of `work`); delete the `panel` column from `work-body`; delete `screens-tabs` and add the blocks `screen-changes` (`ws-changes`) and `screen-files` (`ws-files`), each with `"props": { "screen": true }`, to `screens-body`; set `sidebar-footer` to 125px. An install that keeps its old layout works without errors: the terminals show, the side panel stays hidden, Views is in the tab bar, Changes and Files open only beside, the status bar isn't under a full-size view, and the footer has 28px empty at its foot.

## [0.19.0] - 2026-11-22

### New
- **Settings > Features: turn the package's add-ons off.** A new section, first of the package's in Settings (Features, Agents, Experimental; `ws-switcher.settings/features` opens it), has a switch for each add-on: Board, Notes, Worktrees, History, Automations, Plan usage and Agent numbers. All are on to start with, one setting for every workspace, kept in `~/.herdr/settings.jsonc` as `"features": { "<key>": false }` with comments kept. Off hides it everywhere and stops its background work, at once and without a restart: Board's pill, button and Notes' Move to the board go, and pull requests on cards and GitHub board items aren't followed (no `gh`, no messages to card agents); Notes', Worktrees' and History's pills, buttons, menu rows, footer row and + menu rows go; Automations off starts nothing (schedules, triggers, checks, Run now, `herdr-ws-run`, which exits 3), lets a run already going finish, and back on carries on from then without running late what came due meanwhile; Plan usage off asks nothing (no `claude -p /usage` or `agy -p /usage`); Agent numbers off leaves the Agents rows at the name and status and History without compactions. Nothing is deleted: cards, notes, worktrees, automations, the tab bar's pins and the last usage stay, so on brings it back as it was. The sidebar footer shrinks to the rows it has. Automations' row counts them ("9 automations in 4 workspaces"), and a settings file that isn't valid JSONC greys the switches with everything on. To update, copy `mods/ws-settings`, `mods/ws-switcher`, `mods/ws-agents`, `mods/ws-status`, `mods/ws-tabs`, `mods/ws-chrome`, `mods/ws-new-menu`, `mods/ws-notes` and `mods/ws-history` (the background runner restarts by itself when the switcher's files change, and the switcher rebuilds `ws-settings/main.js` when it reloads).

One open in a Herdr terminal is closed first, but only when the agent running there says it holds it (Claude's `~/.claude/sessions/<pid>.json`, Pi's own note with its pid); it refuses, saying why, whenever an agent may still be writing it: a running Claude anywhere that has it open, a Claude or Pi in its folder that isn't known to hold another conversation, a transcript (or one of its sub-agents') written in the last two minutes, a conversation from the desktop app or an editor used in the last 30 minutes, or helpers still running under it (closing it would end them). ## [0.17.0] - 2026-11-21

### New
- **Extras, a section of Settings.** The sidebar footer's Settings now opens the package's copy of Herdr's Settings window: Herdr's own sections (Look, Machines, Updates and the rest, rebuilt from Herdr's file whenever Herdr updates it, so they stay Herdr's) and, after Privacy, Extras: the package's own settings. Experimental features wait there, each off until you turn it on and saying why it's experimental, next to the package's switches (Keep running, Bring agents back after a restart, Herdr guide), which also stay where they were. The settings are kept in `~/.herdr/settings.jsonc`, written the first time you change one, with what each does in a comment above it; Open the file opens it in your editor, and your edits there show within a minute. The macOS menu's Settings…, the command palette and Herdr's update notices still open Herdr's plain window; if a Herdr update changes its Settings so the copy can't follow, the footer's Settings shows Extras alone with a button to Herdr's, and a toast says so. To update, copy the new `mods/ws-settings`, `mods/ws-switcher`, `mods/ws-chrome` and `mods/ws-agents`. For Cmd+, to open it too, set `"cmd-,"` in the `global` section of your `~/.config/herdr-app/keys.json` to `"mod.open:ws-settings"` (`ws-switcher.settings/extras` opens it on Extras); an edited keys file no longer gets Herdr's new default shortcuts by itself.
- **Wipe Antigravity conversations (experimental).** With it turned on in Settings > Extras, an Antigravity agent's right-click menu gets Wipe session…, but only when the list can tell which conversation that agent is running (a note left by an Antigravity that ended in the same tab gets none). The dialog names the conversation (its title or first prompt, when it was last used, its id and how many sub-agent conversations go with it), and asks a second time when the wipe takes more than one conversation. Wipe takes the conversation and its sub-agents' out of Antigravity's own lists, checks they're gone, and only then moves their files, so History and Antigravity's `/resume` no longer show it. It checks everything it can before it closes the agent, and refuses with nothing changed what it can't read. It's experimental because those lists are files whose format Antigravity doesn't document: each wipe keeps one folder in `~/.herdr/trash/antigravity-<id>-<time>/` with a copy of the lists, what it removed (saved before each change) and the conversation's files, and `node ~/.config/herdr-app/mods/ws-agents/agywipe.js restore "$HOME" <that folder>` puts it all back; move the folder to the Trash once you're sure. While another Antigravity runs, or when it can't tell, nothing is changed: the wipe finishes once it can (History leaves the conversation out meanwhile), and a toast says when it's done, or when it gave up and what was changed. To update, copy `mods/ws-agents` and `mods/ws-history` too.
